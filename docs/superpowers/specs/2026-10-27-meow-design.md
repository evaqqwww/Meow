# Meow mobile interaction

Build the user's specified cat/temple interaction as a Chinese mobile-first static web app, then upload it to the GitHub repository `Meow` and publish GitHub Pages. The cat now uses the user's supplied five-frame PNG sequence, copied without modification; retain the four original PNG assets as well.

The supplied temple is the background. The first sequence frame is the default cat. Tapping the cat opens a text-entry sheet and the phone keyboard. Confirming a nonempty message reveals the supplied pink paw beside the cat. During an uninterrupted 1100 ms hold, keep frame 0 through the first 300 ms, then play the five frames forward over 800 ms, advancing one frame every 200 ms. At elapsed 0/300 ms show frame 0; at 500/700/900/1100 ms show frames 1/2/3/4 respectively. Reaching 1100 ms triggers one blessing for 1000 ms. Keep the cat on frame 4 for as long as the paw remains held, including after the speech disappears.

Release starts reverse playback from the current frame, one frame every 200 ms, until frame 0. A full reverse from frame 4 takes 800 ms; a partial reverse takes the current frame index multiplied by 200 ms. Before 1100 ms, release, pointer cancellation, leaving the target, or hiding the page ends the active hold without a blessing and resets accumulated hold progress. After an interrupted hold's reverse completes, preserve the submitted input and allow a fresh attempt; do not allow another hold during reverse playback. After a successful hold, wait for release and reverse completion (and the 1000 ms reply period) before returning to idle and allowing a new message. If reverse playback ends first, keep the cat on frame 0 until the blessing has been visible for the full 1000 ms. The interaction can be repeated.

Reply content (updated at the user's request): choose one random preset Chinese blessing after a successful hold, excluding a phrase exactly matching the submitted input. Keep that blessing stable throughout the 1000 ms reply and choose again for each completed interaction. Input is limited to 120 UTF-16 code units, can be edited before holding, and cannot be blank; no server or persistence is needed. Use textContent for speech, native dialog semantics, Pointer Events and keyboard hold support. Provide progress and clear Chinese instructions, safe-area spacing, responsive layouts, and reduced-motion support. Preserve all four original PNGs and all five new sequence PNGs without modification.

Approaches considered: a framework adds a build dependency without helping this small interaction; a buildless static app matches GitHub Pages and works without external services. Use static HTML/CSS/ES modules, a testable clock-driven state machine, Node's built-in test runner, and a small static build/preview script. Hosting is GitHub Pages as explicitly requested; Sites hosting is unnecessary.

Acceptance: correct unchanged assets and preloaded five-frame sequence, real text entry, exact forward/reverse frame boundaries, held-last-frame behavior, 1100 ms blessing trigger and 1000 ms speech duration, wait for both reverse playback and speech before resetting, retry only after interrupted reverse completion with input preserved, no accumulated hold time or stale double completion, readable long messages, phone and desktop layout, local tests and browser checks, then verified remote upload and Pages deployment when connectivity permits.
